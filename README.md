# Lumina Bloom

**从城市微气候研究到个性化户外 AI Agent**  
*From Urban Microclimate Research to a Personalized Outdoor AI Agent*

Lumina Bloom 希望帮助长期在室内工作或学习的用户，把“出去走一会儿”变成更容易开始、也更适合自己的日常行动。项目将城市微气候研究与 AI Agent 结合，探索如何根据环境条件、个人日程与长期偏好，安排户外活动的时间、地点和路线。

> 让专业环境预测走进日常生活，也让每一次走到户外，都长成一点变化。

本文依据为 Meta 黑客松准备的中文项目方案整理，介绍研究背景与产品设计。当前仓库提供静态演示与 Flask 应用；各项能力的实现范围见文末“当前原型与研究方向”。

## 一、项目背景

Lumina Bloom 源于我在硕士阶段一门相关课程中的 **Urban Microclimate Forecasting（城市微气候预测）** 项目。在课程中，我围绕城市局部环境开展预测建模研究，涉及环境数据处理、空间特征工程、预测模型训练与特征分析，探索如何结合城市空间形态和气象信息，预测特定地点与时间的微气候条件。

这项研究让我开始思考：城市微气候预测除了应用于建筑与城市设计研究，是否也能帮助普通人在日常生活中做出更好的选择？

城市中的建筑、树冠和街道形态，会使相邻地点呈现不同的日照、遮阴及辐射热环境。这些局部差异会影响户外活动的时间与地点选择，而用户本身的日程、生活习惯和个人偏好，也会进一步影响这些决策。

课程结束后，我出于个人兴趣继续发展这一项目，将微气候预测与 AI Agent 技术结合，构建名为 **Lumina Bloom** 的 Web 应用。我使用 Flask 构建后端，结合 JavaScript 前端、Open-Meteo、OpenStreetMap Overpass 和 LLM API，开发户外活动记录、日历统计、像素植物成长、环境建议及对话交互等功能，并进一步设计环境预测、工具调用与长期记忆相结合的个性化规划能力。

## 二、产品体验：从一次外出到持续陪伴

### LOG：从几分钟开始行动

用户手动记录当天的户外时长，也可以接受或拒绝 Lumi 的建议。记录操作尽量轻量；当用户忙碌、缺少动力或心情不佳时，可以表达自己的状态，为后续交互提供上下文。

### JOURNEY：看见自己的日常轨迹

月历呈现每天的活动记录，让零散的几分钟变成可以回看和积累的过程。用户可以切换月份，查看某一天的活动时长。

### BLOOM：让行动长成一株植物

一株像素植物随累计时长逐步成长，把抽象的坚持转化为可见的变化。Bloom 同时作为陪伴式对话入口，围绕活动体验与日常状态开展交流。

### LUMI LAB：理解建议背后的因素

原型展示近期反馈与行为估计；后续研究希望将环境预测、影响因素和推荐理由带到这一界面，让用户理解建议从何而来。

## 三、城市微气候预测：为时间与地点选择提供环境依据

项目的环境预测研究聚焦于 **Hyperlocal Microclimate Forecasting（超局地微气候预测）**，探索未来 **1—6 小时**内，具体街段、公园和步行地点的日照、遮阴及辐射热环境变化。

核心挑战是整合具有不同空间尺度和时间分辨率的城市形态与气象数据，提取局部环境特征，并结合物理模拟与监督学习构建预测模型。以下为研究方案，尚未作为完整预测服务接入当前仓库。

### 1. 城市几何与环境数据

研究方案涉及的主要数据与工具包括：

- **OpenStreetMap / Overpass API：** 获取公园、绿地、道路及建筑轮廓等空间对象。
- **OSMnx / GeoPandas / Shapely：** 处理空间几何，构建步行街段，分析道路、建筑与户外地点之间的关系。
- **Open-Meteo：** 获取逐小时天气预报、气温、云量和太阳辐射等环境变量。
- **pvlib 与动态遮阴计算：** 结合太阳高度角、方位角、建筑高度及街道几何，计算不同时间的遮阴条件。
- **建筑、地形与树冠数据：** 提取影响局部辐射环境的空间特征。

静态城市形态与动态气象条件共同构成模型输入。数据处理需要完成坐标统一、空间匹配、时间对齐、缺失值处理与特征工程。

### 2. 物理模拟与代理模型

研究方案采用 Ladybug Tools 的 **Outdoor SolarCal**，结合直接与散射太阳辐射、天空暴露、人体遮阴比例、地表反射和长波辐射条件，计算给定环境假设下的平均辐射温度（MRT）参考值。

在此基础上，计划使用 **XGBoost Regression** 训练代理模型，并以 Random Forest 和简单回归模型进行对照。输入特征包括天气与辐射条件、太阳位置、建筑及街道形态、天空可视程度、几何遮阴和时间特征，支持多地点、多时段的快速环境估计。

### 3. 可解释预测

研究方案结合 **SHAP** 分析太阳辐射、建筑遮阴、天空可视程度、街道朝向及气象条件对预测结果的贡献，涵盖全局特征重要性与具体地点、时刻的局部解释。

环境模块将 MRT 估计、遮阴条件、模型解释和数据质量信息交给 Lumi，为活动规划提供环境依据。预测验证需要按天气过程和空间区域划分数据，检查不同条件及未见地点上的表现。

## 四、Lumi Agent：理解需求、调用工具、比较方案

在课程研究之外，我进一步探索如何让 AI 主动利用环境预测能力，根据用户需求制定个性化户外活动计划。

规划方案采用 **ReAct Agent（Reasoning + Acting）**：Lumi 理解用户目标，根据任务需要调用天气、空间分析和环境预测等工具，再结合返回结果继续推理与比较候选。

例如，用户提出：

> “我今天想晒一会儿太阳，但中午太热了，最好也不要走太远。”

Lumi 需要理解三个条件：希望获得一定日照、避免较强的辐射热负荷，并控制步行距离。随后按需调用：

- **天气与环境工具：** 获取未来几小时的天气、太阳辐射、UV 和空气质量。
- **空间检索工具：** 查询附近公园、绿地及其他户外地点。
- **路线工具：** 计算实际步行路线、预计时间及可达性。
- **微气候预测工具：** 比较不同地点和时段的遮阴、MRT 估计及影响因素。

当某个地点在用户偏好的时段环境不合适时，Lumi 可以继续比较其他时间窗口，或寻找附近的替代地点。最终方案应包含 **时间、地点、路线、环境条件及推荐理由**。

### 长期记忆与个性化

长期记忆用于保存与后续规划有关的偏好、活动习惯和重要反馈。系统从对话、活动记录和反馈中整理信息，在新的交互中检索与当前任务有关的内容，帮助 Agent 持续理解用户。

例如，Lumi 可以逐渐了解到：用户通常在工作日傍晚有空，喜欢住处附近的绿地，工作繁忙时更愿意选择十分钟左右的活动。当用户拒绝建议、改变日程或表达新的偏好时，相关记忆也需要更新。

活动时间、地点和完成状态等精确信息则由结构化记录保存，支持日历统计与长期回顾。

### Lumi 与 Bloom 的分工

- **Lumi Planning Agent：** 理解用户目标、调用环境与规划工具、比较候选方案，并生成和调整活动计划。
- **Bloom Companion Agent：** 围绕活动记录与长期习惯开展陪伴式交流、活动复盘和反馈收集。

在设计中，两者共享与当前任务有关的记忆和活动上下文：Lumi 帮助制定计划，Bloom 在活动后了解实际体验，将新的偏好与反馈用于后续规划。

### 主动调整计划

对于用户已经确认的活动，设计中将保存时间、地点、环境依据及当前状态。当后续天气预报或环境预测发生明显变化时，Lumi 可以重新查询信息、比较替代时间或地点，并提出调整建议；用户确认后再更新计划。

## 五、当前原型与研究方向

当前仓库承载产品原型，研究方案中的能力按阶段逐步接入。

| 能力 | 当前状态 |
| --- | --- |
| 户外时长记录、月历、像素植物成长 | 已在原型中实现，记录保存在当前浏览器 |
| 天气与附近地点查询 | Flask 应用可调用 Open-Meteo 与 OpenStreetMap / Overpass；静态版使用示例数据 |
| 提醒与陪伴聊天 | 默认使用规则或预设回复；Flask 应用可选配置模型服务 |
| 微气候模拟、XGBoost 与 SHAP | 研究与升级方向，当前仓库未包含完整训练与预测链路 |
| ReAct 规划、长期记忆共享与主动重规划 | 产品与技术设计方向，当前原型未完整实现 |

LUMI LAB 中的压力、恢复负荷与行为概率为原型演示指标。手动记录的户外分钟数也不等于设备自动测得的日照量。

### 本地体验静态 Demo

在仓库根目录运行：

```bash
python3 -m http.server 8000 --directory demo
```

打开 <http://localhost:8000>。静态版不需要 API 密钥，使用示例天气、地点与本地规则回复；首次进入包含示例历史记录。

### 本地运行 Flask 应用

需要 Python 3.10+：

```bash
cd lumi-web-app
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

打开 <http://127.0.0.1:5000>。Windows 可使用 `py -3` 创建虚拟环境，并运行 `.venv\Scripts\python.exe`。默认使用规则提醒；模型能力按需配置服务器环境变量。

部署与模型配置见 [部署说明](docs/DEPLOYMENT.md)，检查范围见 [验证记录](docs/VALIDATION.md)，字体来源与许可证见 [第三方说明](THIRD_PARTY_NOTICES.md)。

仓库已包含 Netlify 静态部署配置，发布目录为 `demo/`；当前 README 尚未收录经核实的公网体验网址。
